# Payment Processing API Testing Requirements
# Test ID Prefix: PAY

## Payment Creation & Processing (PAY-001 to PAY-020)

PAY-001: Create payment with valid card details
- Accepts card number, exp_date, cvv, amount, currency
- Returns payment ID and status: pending
- Validates card number (Luhn algorithm)
- Validates expiration date not in past

PAY-002: Process payment successfully
- Status changes from pending → processing → completed
- Webhook notification sent
- Receipt generated and emailed
- Payment recorded in ledger

PAY-003: Declined card returns proper error
- Returns 402 Payment Required
- Error message: "Card declined"
- No charge made
- Reason code included (insufficient_funds, etc.)

PAY-004: Expired card rejected
- Validates expiration date
- Returns 400 with clear message
- No payment attempt made

PAY-005: Invalid CVV rejected
- CVV must be 3-4 digits
- Returns 400 Bad Request
- Security audit logged

PAY-006: Amount validation
- Minimum: $0.50 (or currency equivalent)
- Maximum: $999,999.99
- Two decimal places only
- Returns 400 for invalid amounts

PAY-007: Currency support
- Supports: USD, EUR, GBP, JPY, etc.
- ISO 4217 currency codes
- Proper decimal handling per currency
- Returns 400 for unsupported currency

PAY-008: Idempotency keys prevent duplicate charges
- Same idempotency key returns same result
- Duplicate requests within 24 hours detected
- Returns 200 with original payment

PAY-009: 3D Secure authentication flow
- Redirects to bank for authentication
- Handles authentication success/failure
- Completes payment after successful auth
- Times out after 10 minutes

PAY-010: Payment method tokenization
- Can save card as token for future use
- Token is PCI-compliant
- Original card details not stored
- Token can be used for subsequent payments

PAY-011: Payment with saved token
- Uses stored payment method
- Skips card detail validation
- CVV still required for CVC check
- Returns 404 if token not found

PAY-012: Multiple payment methods per customer
- Can store multiple cards/payment methods
- Each has unique ID
- Can set default payment method
- Can delete payment methods

PAY-013: Payment description and metadata
- Custom description for statement
- Metadata key-value pairs stored
- Retrievable with payment details
- Max 50 metadata keys, 500 chars per value

PAY-014: Customer information attached to payment
- Email, name, address optional
- Used for receipt and fraud detection
- Billing address separate from shipping
- Phone number for verification

PAY-015: Payment intent creation
- Two-step process: create intent, confirm payment
- Allows validation before charging
- Intent expires after 24 hours
- Can be cancelled before confirmation

PAY-016: Automatic payment retry on soft decline
- Soft declines retried automatically
- Max 3 retry attempts over 7 days
- Customer notified of retry schedule
- Hard declines not retried

PAY-017: Payment holds/authorizations
- Authorize amount without capturing
- Hold valid for 7 days
- Can capture partial or full amount
- Uncaptured amounts released automatically

PAY-018: Capture authorized payment
- Must be within 7 days
- Can capture less than authorized (tip scenarios)
- Returns 400 if already captured
- Returns 410 if authorization expired

PAY-019: Void/cancel payment before capture
- Cancels authorization hold
- No charge to customer
- Returns 200 if successful
- Returns 400 if already captured

PAY-020: Payment timeout handling
- Payments timeout after 15 minutes
- Status changes to failed
- Customer notified
- Funds not captured

## Refunds (PAY-021 to PAY-030)

PAY-021: Full refund of completed payment
- Refunds entire amount
- Returns refund ID
- Status: pending → completed
- Customer notified via email

PAY-022: Partial refund
- Can refund less than original amount
- Multiple partial refunds allowed
- Total refunds cannot exceed payment amount
- Each refund tracked separately

PAY-023: Refund to original payment method
- Funds returned to original card
- Takes 5-10 business days
- Status updates tracked
- Webhook notifications sent

PAY-024: Refund validation
- Cannot refund more than remaining balance
- Cannot refund unsuccessful payment
- Cannot refund after 180 days (policy dependent)
- Returns 400 with clear error

PAY-025: Refund with reason
- Reason codes: duplicate, fraudulent, requested_by_customer
- Reason stored with refund
- Used for analytics and dispute management
- Optional notes field

PAY-026: Instant refunds
- For eligible transactions
- Funds available immediately
- Higher fee
- Not available for all cards

PAY-027: Dispute management
- Customer can dispute payment
- Status changes to disputed
- Evidence can be uploaded
- Automatic hold on funds

PAY-028: Refund fees
- Standard refunds: no fee
- Instant refunds: $0.25 fee
- Returned to merchant account
- Proper accounting

PAY-029: Refund idempotency
- Same refund request returns same result
- Prevents duplicate refunds
- Idempotency key required

PAY-030: Refund webhooks
- refund.created, refund.updated, refund.completed events
- Includes full refund details
- Retry on failure (exponential backoff)
- Webhook signature verification

## Compliance & Security (PAY-046 to PAY-060)

PAY-046: PCI-DSS compliance
- Never store full card numbers
- Use tokenization
- Encrypt data in transit (TLS 1.2+)
- Encrypt data at rest

PAY-047: Strong Customer Authentication (SCA) for EU
- 3D Secure 2 for card payments
- Required for >€30 transactions
- Exemptions handled (low-risk, recurring)
- Falls back gracefully

PAY-048: Address Verification System (AVS)
- Checks billing address with issuer
- Returns match/no match result
- Used for fraud scoring
- Optional but recommended

PAY-049: CVV verification
- Checks card security code
- Not stored after verification
- Required for card-not-present
- Failure increases fraud score

PAY-050: Fraud detection
- Machine learning models score transactions
- Rules engine (velocity checks, blacklist)
- Manual review queue for high-risk
- Block/allow lists by email, card BIN, IP

PAY-051: 3DS exemptions
- Low-value transactions (<€30)
- Recurring payments after first
- Merchant-initiated transactions
- Low-risk (SCA engine decision)

PAY-052: Geolocation validation
- Card issuer country matches IP location
- Mismatches flagged as suspicious
- Configurable risk thresholds
- Can block high-risk countries

PAY-053: Velocity limits
- Max transactions per card per hour/day
- Max amount per customer per day
- Prevents card testing
- Returns 429 when exceeded

PAY-054: Webhook signature verification
- HMAC-SHA256 signature in header
- Timestamp to prevent replay attacks
- Verifies payload integrity
- Returns 401 if invalid

PAY-055: API key security
- Secret keys never in frontend
- Publishable keys for client-side
- Key rotation support
- Audit log of key usage

PAY-056: Data retention policies
- Card data deleted after tokenization
- Transaction data retained 7 years (legal requirement)
- Personal data deletion on request (GDPR)
- Automatic purging of old logs

PAY-057: Audit logging
- All payment operations logged
- Immutable log storage
- Includes: who, what, when, IP, result
- Searchable for compliance audits

PAY-058: Rate limiting per merchant
- API calls per minute/hour
- Prevents abuse
- Different limits per endpoint
- Returns 429 with Retry-After

PAY-059: Chargeback handling
- Notification when chargeback filed
- Evidence submission deadline
- Track chargeback status
- Deducted from account balance

PAY-060: Regulatory reporting
- Generate reports for auditors
- PCI-DSS validation documents
- Transaction summaries by period
- Compliance dashboard
